How the branch is put together, so the shape can be reviewed before the PR:

**Example script** (`examples/explainability/captum_attribution.py`). One file, argparse, no framework. `--model tiny` runs an MLP with `IntegratedGradients` and no downloads; `--model <HF causal LM>` runs `LayerIntegratedGradients` on the input embeddings with `logits_to_keep=1` so the `[steps, T, V]` logits tensor is never materialised. `--precision`, `--steps`, `--runs`, `--internal-batch-size`, `--compile` and `--profile-dir` cover the knobs the case study discusses. The script always computes the same attribution on CPU and prints max relative error, so every number in the docs is reproducible with one command. Execution mode is whatever the environment says (`TORCH_TPU_DEFER_AND_FUSE=1` for DeferAndFuse), which keeps the script identical across the three rows of the comparison table.

**Case study** (`docs/source/case_studies_explainability.py`, Marimo source of truth, exported to `docs/case_studies_explainability.md` the same way the existing case studies are). Seven sections, in the order a reader hits the problems: run Captum on a TPU; set the matmul precision (with the 1e-3 vs 1e-7 table); compare the execution modes on Qwen3-0.6B; read the XProf operator table (`aten::_to_copy` at 70% of host time in strict eager); bound peak memory; check the convergence delta; run the example. It links to the existing precision guide instead of repeating it, and follows the docs style skill (second person, sentence case, tables wrapped in `mdformat off/on`).

**Wiring.** `mkdocs.yml` nav, `docs/source/index.py` and `docs/index.md` case-study lists, `examples/README.md` entry. `mkdocs build --strict` passes. ruff excludes examples/docs already so no lint config changes.

**Dependencies worth flagging.** The strict-eager and DeferAndFuse rows work on 0.2.0 as released. The `torch.compile` row needs #6106 (CPU view arguments in split compile) and meta-pytorch/captum#1952 (LIG offsets as Python ints); the text says so and the script still runs without them, it just reports the failure for that mode.

Happy to adjust scope, for instance dropping the LLM path to keep the example download-free, or splitting the docs page from the script. I would like to own this issue; non-collaborators cannot self-assign, so if a maintainer can assign me, I will open the PR the moment a slot frees.
